## Implemented systems and ownership

- `PlayerVisualAnimator` drives a 2D directional locomotion blend from actual CharacterController velocity in the gameplay root's local X/Z axes. Forward, backward, and left/right strafe use seven editor-baked KayKit clips including takeoff, air, and landing; the original source FBX remains Generic. The existing idle clip has a small, gated torso/shoulder/head breathing layer with no gameplay-root displacement. `Phasebreak > Author Directional Player Locomotion` rebuilds the clips and existing controller without duplicating states or blend trees. Movement, facing, jump physics, equipment ownership, and combat outcomes remain with their existing owners; Animator root motion stays off.
- Directional locomotion was compiled and inspected in the already-open Unity 6000.6.1f1 StarterZone_V2 client on main revision `83acd8a` (the subsequent `6132fc5` wilderness merge fails compilation). Three 1080p implementation passes corrected retargeted body height, stride phase, and inherited foot IK; a final 720p pass covered all eight directions, start/stop/reversal, keyboard turns, and takeoff/air/landing. Synthetic Input System events exercised actual movement and right-mouse steering. Eleven-second idle checks showed torso motion with zero root drift, and disabling breathing left zero residual spine rotation. Watchsteel Saber/Trailwarden Helm/Warden Plate and Bloodwake Edge/Bloodcrest Visor/Bastion Aegis remained attached through locomotion, jump, auto-attack, Strike, Crushing Blow, Quickstep, Phase Dash, Phase Lunge, and Flicker; Flicker restored every renderer. Original save payloads were restored after QA. Playback is capped, so fast movement and slopes retain some foot sliding; there is no terrain foot locking. Physical keyboard/mouse feel and packaged-build verification remain untested.

- StarterZone_V2 has open-world death recovery through `OpenWorldRecovery`: a 1.25-second defeated state, nearest available scene-authored checkpoint, safe movement teleport, full health, and cleared target/combat/talent transients. The trailhead is always available; Northgate, Westmere and Eastwatch use `QuestJournal`'s existing saved discovery flags. `PlayerProgression.ApplyDeathPenalty` deducts integer `CurrentExperience / 10` (rounded down), saves through existing progression persistence, and never changes level. Rift Crypt remains authoritative inside the dungeon and does not incur the open-world penalty.

- `PlayerCombat` owns a rebindable **F** auto-attack toggle, shown as armed/off above the five-slot action bar. Armed basic melee swings use only `PlayerTargeting.CurrentTarget`, a 2.4 m range with line-of-sight checks at start and impact, 3 base damage, and a 1.8 s interval divided by the existing build attack-speed multiplier (minimum 0.5 s, also bounded by swing recovery). The shared melee routine uses a 0.3 s windup and 0.35 s recovery; valid active abilities preempt a basic swing. Basic attacks consume no Energy, charges, or global cooldown. Progression/build power, boss modifiers, crits, hit feedback, melee poses, audio, and the equipment draw/sheath timer use existing owners. Menus/chat pause armed attacks, while death, disable, and combat reset disarm them. Target loss/death leaves the toggle armed but causes no acquisition or damage until the player selects another valid target. Auto-attack state is not saved; only its binding uses existing Settings persistence.
- `Assets/Phasebreak/Scripts` owns third-person movement, jump/air control, camera, targeting, interaction, thirteen combat abilities with 24 assignable action-bar slots, Energy, health/death, XP/levels 1–10, inventory/equipment, set effects, specialization, talents, quests, enemy encounters, and Rift Crypt checkpoint recovery. UI and debug tools should use these owners rather than duplicate gameplay state.

Regeneration and crit-resource procs are suspended during the sequence; internal hits do not trigger mobility kill recovery, Rift Chain, charge refunds, or Rift Mark consumption.
